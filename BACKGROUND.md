# Фоновая обработка

По указанию владельца от 04.11.2026 длительные задания запускаются в фоне.
`run_background.py` запускает отдельный процесс без терминала, сохраняет
метаданные и сразу возвращает управление. Используется тот же Python и CLI
фреймворка; ключи берутся из существующей конфигурации или окружения.

```bash
cd /work/video_voice_ai_manager
python3 run_background.py voice /work/tg/files/example_voice.ogg
```

Команда выводит JSON с PID и путями задания, лога и результата. Временные
файлы находятся в каталоге задания. По умолчанию результат записывается
в `vvam_output/background/<job>/transcript.md`.

Можно задать привычные параметры CLI:

```bash
python3 run_background.py voice /work/tg/files/example_voice.ogg \
  -o /work/video_voice_ai_manager/vvam_output/example.md

VVAM_GEMINI_AUDIO_MODEL=gemini-2.5-flash \
  python3 run_background.py voice /work/tg/files/example_voice.ogg
```

Второй пример использует поддерживаемый фреймворком обычный Gemini API вместо
Live API. Это не автоматическая смена ключа и не повтор авторизации.

Однократная проверка:

```bash
python3 run_background.py status /work/video_voice_ai_manager/vvam_output/background/<job>
```

Статус содержит код выхода и наличие выходного файла. Завершение процесса
нужно отличать от содержательной приёмки расшифровки. При ошибке сохраняется
лог; автоматического повторного запроса или смены ключей нет.

Совпадающее активное задание повторно не запускается. Успешно завершённое
совпадающее задание также возвращается из журнала. Чтобы намеренно получить
другой вариант, задайте другой выходной файл или модель. Существующий
выходной файл не перезаписывается новым заданием.

Не ждать процесс в чате и не строить цикл опроса статуса без прямой просьбы
владельца. Не останавливать текущие обработки ради смены способа запуска.
